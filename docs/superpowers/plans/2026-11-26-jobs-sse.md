# Jobs and server-sent events Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Persisted jobs with throttled progress, an in-memory event bus,
and `GET /api/v1/jobs`, `/jobs/{id}` and `/events` (SSE over an
authenticated `fetch`), as the infrastructure later features build on.

**Architecture:** `domain` gets `Job` and `Event`; `ports` gets
`JobRepository` and `EventBus`; `application` gets the job use cases and
`JobHandle::run`; `sqlite` stores jobs; a new adapter crate
`events-memory` implements the bus over `tokio::sync::broadcast`; `http`
serves the routes and the stream; `app` wires it, recovers jobs at
startup and ends streams on shutdown.

**Tech Stack:** Rust 2024, axum 0.8 (`axum::response::sse`), utoipa 5,
sqlx 0.8 (SQLite), tokio, futures-core / futures-util, tokio-stream.

**Spec:** `docs/superpowers/specs/2026-11-26-jobs-sse-design.md`

## Global Constraints

- `domain`, `ports`, `application` reach no I/O crate (`tokio`,
  `tokio-stream`, `axum`, `sqlx`…): `server/crates/app/tests/layering.rs`
  must keep passing. `futures-core` and `futures-util` are allowed.
- Progress throttle: 0.3 s (`TimeDelta::milliseconds(300)`), measured
  with `Clock`. The end always saves and publishes.
- Retention: jobs whose `finished_at` is older than 30 days are deleted
  at startup.
- Bus capacity: 256. SSE: `retry: 3000` first, `: ping` every 15 s,
  `X-Accel-Buffering: no`.
- `JobKind`: `[a-z][a-z_]*`, at most 32 characters.
- Error messages and job errors in English; DTO dates RFC 3339 UTC.
- No domain type serialized to the client: DTOs in `http`.
- `mise run ci` passes at the end of every task; `Cargo.lock` is
  committed with any new dependency (`--locked`).
- Test data is invented. Commits follow Conventional Commits with the
  scopes of `CLAUDE.md`, ending with the session's attribution lines.

## Review Focus

- A client that disconnects mid-stream releases its bus receiver (no
  leak, no growing lag): Task 4 pins it with `receiver_count`.
- Many concurrent workers stepping one job lose no count: Task 5.
- A failing progress save does not stop or fail the job: Task 5.
- `GET /jobs/abc` (non-numeric id) answers 404 `not_found`, not 400:
  Task 6.
- `total` unknown serializes as `null` and is required-nullable in the
  contract (the client must not treat it as missing): Task 6.
